# Product synthesis

Product laws — the boundaries that keep Mimir coherent.

1. **Activities are the execution UI.** Terminals, agents, apps, and routine
   runs use one lifecycle and one sidebar tray.
2. **One registry, small public projection.** UI runtimes share the internal
   registry; agents see only the explicit Workbench, Graph, Chat, and
   Connections allowlist.
3. **The Editor is the review surface.** Activity navigation never replaces
   the document being reviewed.
4. **Files is workspace navigation.** Lazy project tree, editor-derived
   recents, per-workspace favorites, typed previews, global quick-open — one
   indexed workspace boundary.
5. **Power extends through the kernel.** New capabilities arrive as a tool,
   app, routine, launcher preset, or Activity — not permanent UI.
6. **Trusted and hackable beats administered.** Configuration is local and
   explicit; the product assumes a small trusted team.
7. **Permanent navigation stays Sidebar, Activity, Editor.** Chats is the one
   team communication surface; other workflows belong in Apps, tools,
   Routines, or launcher presets.
